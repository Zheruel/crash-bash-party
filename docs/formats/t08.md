# Type 0x08: texture set (Crash Bash, PS1)

Archive entries with type id 8 (`NNNN.t08.bin`). A set of CLUTs plus 4bpp/8bpp indexed textures,
normally paired with the following `t29` model. All little-endian. Decoder: `tools/t08.py`.
Verified over 400 of 401 files (all parse to exact EOF; ~15,160 textures). `0151.t08.bin` is **not** a texture set
(it is a text string table, "OBJECTIVE / PICK UP AND THROW CRATES...").

There is **no VRAM x/y anywhere in the format.** The engine packs textures into VRAM at load time, so there is no
VRAM sheet. A model references a texture by block index; the palette comes from that block (see below).

Confidence: H = verified on all files, M = consistent with data but meaning inferred, L = guess.

## Layout

```
0x00  header (0x20)
0x20  CLUT section   (num_cluts records)
....  texture section (num_textures blocks)
....  extra section (only if header.extra_offset != 0)  OR  zero trailer (4, 8 or 12 bytes)
```

### Header (0x20 bytes)
| off | type | name | meaning | conf |
|---|---|---|---|---|
| 0x00 | u32 | type | always 8 | H |
| 0x04 | u32 | size | file length | H |
| 0x08 | u16 | num_textures | texture blocks (animation frames count as blocks) | H |
| 0x0A | u16 | num_cluts | CLUT records. May be larger or smaller than num_textures | H |
| 0x0C | u32 | tex_rel | offset of texture section relative to 0x0C (= CLUT end - 12) | H |
| 0x10 | u32 | clut_bits | always 16 (bits per palette colour) | M |
| 0x14 | u32 | unk14 | varies per file (e.g. 22980, 25096), not size-related, differs between same-layout files. Probably a hash/id | unknown |
| 0x18 | u32 | extra_offset | 0, or file offset of the extra section (== end of texture section) | H |
| 0x1C | u32 | pad | always 0 | H |

### CLUT record
`u32 n` (16 or 256) then `n` x u16 PS1 BGR555 (bit15 = STP). Stride `4 + 2n`. 
Colour 0x0000 = transparent; everything else opaque (STP only matters for semi-transparent modes, left to the renderer). H

### Texture block (20-byte header + pixels)
| off | type | name | meaning | conf |
|---|---|---|---|---|
| +0 | u16 | w16 | width in 16-bit units (halfwords) | H |
| +2 | u16 | h | height in rows | H |
| +4 | u8 | crop_x | used-rect x, in bytes (px = bytes*2 for 4bpp) | H (tight bbox of non-zero indices, exact on 9007/9007 tested) |
| +5 | u8 | crop_y | used-rect y, rows | H |
| +6 | u8 | crop_w | used-rect width in bytes | H |
| +7 | u8 | crop_h | used-rect height | H |
| +8 | u32 | zero | always 0 | H |
| +12 | u32 | ref | low 16 bits: CLUT ref; high 16 bits: flags | see below |
| +16 | u32 | frames | 1 normally; N>1 = animation head | M |
| +20 | | pixels | `w16*2*h` bytes, row-major | H |

`ref` low 16 bits: bit0 = 1 means 8bpp (CLUT must have 256 colours), else 4bpp (16 colours);
CLUT index = `ref >> 1`; the value `0xFFFE` means "last CLUT in file" (the stock 16-step grey-ramp CLUT).
CLUT size/bpp matched on 100% of blocks. H.
`ref >> 16` flags: 0 (14985 blocks) or 3 (175 blocks, only in animated sets like 0308). Meaning unknown. L

Pixel size: 4bpp width = `w16*4` px, 8bpp width = `w16*2` px. 4bpp: low nibble is the left pixel. H

Animation, in-file form (M): a block with `frames = N > 1` is followed by N-1 blocks with `frames = 1` and the same
CLUT ref; the N blocks are the frames (all same size). Seen in 0308 etc. (381 groups).

### Extra section (86 of 400 files)
Starts with u32 `kind`, then u32, u32 count, u32 entry_bytes. Two kinds seen. Raw bytes are saved as `extra.bin`.
* kind 8 (65 files): animated textures whose frames are not stored as blocks. Entry (5 x u32): `tex_block_index, frames,
  16-or-128, 0, offset`, followed by a per-frame offset table and frame data (frame stride 124 or 28 bytes,
  smaller than a raw frame; likely compressed/delta). Not decoded. L
* kind 0 (21 files): entries of `u32 tex_block_index, s32 value, 0, 0`; value looks like a UV scroll speed. L

Blocks with `frames>1` but no following frame blocks are heads of kind-8 animations (136 blocks).

### Trailer
When `extra_offset == 0` the file ends with 4, 8 or 12 zero bytes (314 files). M

## Outputs of t08.py
Per input: `texNNN.png` (RGBA, own CLUT), `cluts.png` (one row per CLUT), `sheet.png` (contact sheet, placements in JSON),
`meta.json` (header, CLUT colours, per-texture width/height/bpp/clut/frames/crop/flags/file_offset, `extra`), `extra.bin`.
`--all-cluts` also writes every bpp-compatible CLUT combination as `texNNN_clutMMM.png`.

## Palette selection and the t29 (verified)
Decoding is unchanged and correct: each block's own CLUT (`ref >> 1`, `0xFFFE` = last) reproduces the colours of the
real game for all eight playable characters (compared against emulator screenshots, `docs/reference/`). Notes:
* The last 16x16 block of many model sets is a **colour swatch** (4x4 pixel blocks, own 16-colour CLUT). Polygons
  sample single pixels of it to get flat colours (jeans, shoes, fur shadows). The t29 marks them with texture-run
  bit 15 (see t29.md); the bit is not a table select.
* Every non-zero CLUT colour in the 400 sets has STP (bit 15) = 1; colour 0x0000 is the only transparent value.
* Block ids >= `num_textures` referenced by a t29 are not in the set (unknown source).

## Unknowns
unk14 (header 0x14); ref high-16 flags; exact kind-8/kind-0 extra semantics and frame compression;
source of t29 texture ids past the end of the set.
