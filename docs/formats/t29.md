# Type 0x29 (t29) — 3D model / scene files

Crash Bash (USA). Files `NNNN.t29.bin` in `CRASHBSH.DAT` (399 of them), always paired with the
preceding `(NNNN-1).t08.bin` texture set. Decoder: `tools/t29.py` (pure Python, exports glTF to
`assets/models/`). Reverse-engineered from the data plus the GTE draw routines in `SCUS_945.70`
(strip draw loop at `0x800193a8`, packet builders `0x80017b08`/`0x80017ee8`/`0x80017d90`,
morph blend `0x8001c0f0`, object dispatcher `0x80019a60`).

Confidence: **H** verified by code and by data (all files), **M** consistent with code/data but
not exhaustively verified, **L** guess.

## Conventions

- Little endian. "rel" = self-relative pointer: `target = address_of_the_field + value`, 0 = null (H).
  Parts that share data (e.g. 7 identical meshes) point to the same target, which proves this.
- Vertex coordinates are int16 in model space, Y down, raw units (not 4.12). Sizes: props ~100-600,
  sky domes ~6500. No normals are stored; shading is baked into vertex colours (H).
- A file is: header, part table, mesh data, UV/colour tables, then (when `hdr[0x50] < size`) a
  2048-aligned *tail* holding vertex animations.

## Header (offsets in file)

| Off | Field | Conf |
|---|---|---|
| 0x00 | u16 type = 0x0029, u16 0x0c16 (constant, meaning unknown) | H / - |
| 0x08..0x18 | small tables of per-mesh trailing data (`0x4e9c`...): unused by decoder | L |
| 0x1c | rel -> table of 12-byte records `{i32,i32,i32}` used for runtime "mesh by id" lookup (ids 0x5000+n); points at meshes that are not in the part table, see *Extra meshes* | M |
| 0x20 | rel -> **colour table**: `{u8 r,g,b,pad}` entries, 0x80 = neutral. Runs up to the UV table | H |
| 0x24 | rel -> **UV table**: u16 per entry, `u | v<<8`, pixel coords in the texture | H |
| 0x28 | rel -> model-level **vertex pool** (6-byte `int16 x,y,z`) used by animation groups whose record has no own pool | H |
| 0x3c, 0x48, 0x4c | rel pointers to tiny tables at end of body, unknown | L |
| 0x40 | u32 animation group count | H |
| 0x44 | rel -> animation group descriptors (see below) | H |
| 0x50 | u32 end of body. Tail (if any) starts at next 0x800 boundary; equals file size when there is no tail | H |
| 0x54 | u32 part count | H |
| 0x60 | part table, 0x34 bytes per part (the last part's final 8 bytes overlap the first mesh data; only words 0..9 are used) | H |

Files with part count 0 and tiny header (120 bytes, `hdr[0x50]=0x78`, 22 files) are empty stubs.
Five files (0135, 0627, 0681, 0691, 0715) have no part table at all; their meshes are only
reachable through the 0x1c table and are found by scanning (below).

## Part entry (0x34 bytes at `0x60 + 0x34*k`)

| Off | Field | Conf |
|---|---|---|
| +0x00 | u32 flags. bits 0-11 = triangle count (matches decoded count in 100% of 5956 meshes); bit 18 (0x40000) always set for plain meshes; 0x20000 / 0x10000 set on small billboard/quad parts (0x60xxx, 0x70xxx), meaning unknown | H (count) / L (bits) |
| +0x04 | 0 | - |
| +0x08 | rel -> **vertex block** | H |
| +0x0c | rel -> **strip control** | H |
| +0x10 | rel -> **UV index list**, u16 per triangle | H |
| +0x14 | rel -> **texture run list**, u16 entries | H |
| +0x18 | rel -> **colour/flags list**, u16 per triangle | H |
| +0x1c | rel -> small per-mesh block (20 bytes of mostly 0x200 words), unknown | L |
| +0x24 | rel -> 20-byte block `{i16,i16,i16 ...,x,y,z,...,0x4000}` present on some parts; looks like node info (a translation like `(126,-312,0)`); unknown | L |

Mesh data order in memory (ascending): strip control, vertex block, UV index list, texture runs,
colour list. The vertex block ends exactly where the UV index list starts (used as a check).

### Vertex block (H)
20-byte header: `int16 bbox[6]` (min/max, Y order not fixed), `int16 centre[3]`, `int16 radius`.
Then `nvert` records of 8 bytes: `int16 x,y,z; u16 w`. `w` bit0 = last vertex of its strip, bit1 =
"no back-face cull" for that triangle (from the draw loop; the decoder ignores both and emits
double-sided geometry). `nvert = sum(count+2)` over all strips.

### Strip control (H)
Pairs `(flag u8, count u8)` terminated by `count == 0xFF`. A strip with `count = n` consumes `n+2`
consecutive vertices and yields `n` triangles `(v[i],v[i+1],v[i+2])`; winding alternates per
triangle. `flag` bit0 set = untextured Gouraud triangles (GP0 0x30/0x32), clear = textured
Gouraud (0x34/0x36). Other flag bits (0x08 = seen in sky domes, 0x1f/0x20 etc.) unknown (L).

### Per-triangle lists (H)
Index `t` runs over all triangles of the mesh in strip order.
- UV list[t] (u16) = index `i` into the UV table; the triangle's three UVs are table entries
  `i, i+1, i+2`.
- Colour list[t] (u16): bits 0-12 = index `c` into the colour table, the three vertex colours are
  entries `c, c+1, c+2` (`r,g,b`); bit 15 = semi-transparent; bits 13-14 = PS1 blend mode (ABR).
  Textured colours are modulated x2 (0x80 = 1.0) by the GPU.
- Texture runs: u16 `{bits 0-8 texture id, bits 9-14 run, bit 15 table select}`. One entry covers
  `run+1` consecutive triangles (also counted for untextured triangles). Texture id indexes the
  textures of the paired t08 (file number - 1): 99.998% of UVs fall inside the texture size, and
  98% of ids are in range. Entries with bit 15 set (~2% of triangles) use a different, global
  texture table that is not in the t08; the exporter marks them `texture_table = 1`.

### Extra meshes (H for format, M for completeness)
71 files contain meshes with the same layout that are not in the part table (reached through the
0x1c table at run time). The decoder finds them by scanning 4-aligned offsets for an entry with
flags>>12 in {0x40,0x50,0x60,0x70}, valid pointers, `ntri == flags & 0xfff` and
`vertex_block_end == uv_list`. No false positives were seen. They are exported as `extra_<offset>`.

## Animation: vertex morph keyframes (tail)

Descriptors: `hdr[0x40]` entries of 24 bytes starting at `rel(0x44) - 4` (H):
`{u32 ?; u32 tail_offset (absolute); u32 end; u32 n_frames; i32 ? (rel); u32 rate}`.
`rate` (e.g. 0x1333, 0x9d1) is probably a 4.12 speed, unverified (L).

At `tail_offset` T there are `n_frames` 16-byte records `{u32 z; rel A; rel B; i32 w}` (H):
- frame = blend of keyframe block A and B with weight `w/4096` (B = 0 means exactly A).
  Typical pattern: A, A->B at 1/3, A->B at 2/3, B, ...
- `z` of record 0 (when non-zero) is a rel pointer to the group's **vertex pool**; when 0 the
  model-level pool (`hdr[0x28]`) is used.
- Keyframe block = 20-byte bbox header + `nvert` u16 entries, 4-byte padded. Entry
  `e`: position = pool[`e >> 2`] (int16 x,y,z, 6-byte stride), `e & 3` = the vertex `w` flag bits
  (matches the static mesh's `w & 3` for every vertex checked).
- The block size selects the target mesh: `nvert` of exactly one mesh (or the nearest by position
  when several share a count). Static vertex positions are the base pose.

1028 of 1036 groups decode; the rest are single-frame or unmatched. Frame rate is unknown; the
exporter assumes 30 fps.

## What is not decoded

- **Skeleton / part hierarchy / per-part transforms**: none found. Parts are in model space and
  instanced by game code (e.g. 7 identical box parts with different texture ids). Animation is vertex morph
  only; there are no bones.
- Alternate texture table (texture-run bit 15), strip flag bits other than bit0, vertex `w` bit1
  culling behaviour, part flag bits 16/17, the `+0x1c`/`+0x24` per-part blocks, header words
  0x08-0x18/0x3c/0x48/0x4c, group descriptor `x`/`rate` fields.
- Exact semi-transparency rendering and texture clut selection (clut comes from the t08).

## glTF export notes

- One `.gltf` + `.bin` per file in `assets/models/NNNN.*`. Root node scale `(1/1024, -1/1024,
  -1/1024)` converts PS1 raw units (Y down) to Y-up; geometry is stored raw.
- One node/mesh per part (`partK`, `extra_<hex offset>`), non-indexed triangles, `COLOR_0`
  (textured: x2 clamped), `TEXCOORD_0` normalised by the actual PNG size, one primitive per
  (texture, table, blend) material. Materials carry `extras` with `texture_index`,
  `texture_table`, `semi_transparent`, `abr`. Texture images are linked to
  `../textures/<NNNN-1>/texNNN.png` when run with `TEXROOT`.
- Animated meshes carry one morph target per keyframe (positions as deltas from the base pose)
  and one glTF animation per group animating the node's `weights`.
